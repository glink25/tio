# Tio 0.1.0-rc.8 测试与发布计划

候选版本使用 `preview` 索引，动态包 revision 为 `1009`。Android 与桌面构建号为 `1009`，iOS 构建号由 Xcode Cloud 分配。原生桥接版本为 `4`，iOS 审核基线为 `2`。五个原生渠道重建宿主；Web 部署到 Cloudflare Pages 预览。发布步骤见[发布与更新](releases.md)。

## 发布顺序

1. 冻结依赖，运行 `corepack pnpm check` 和 `corepack pnpm test:e2e`，检查发布脚本语法。提交并推送后，等待 `main` 上对应提交的 `quality` 通过。
2. 下载并验证稳定与预览的签名基线，生成六个平台的计划。检查构建号、渠道与契约，再原子推送 `v0.1.0-rc.8` 与 `host/ios-store/v0.1.0-rc.8`。
3. 按平台核对实际分发结果。使用独立测试空间，从各自的发布入口安装或打开候选版本，记录版本、构建号、系统、设备与失败证据。区分构建通过、渠道可用和真机验收。

## 暂停与恢复

数据丢失、跨空间写入、签名失败或已确认更新无法启动时暂停受影响渠道。对构建或分发失败，按发布文档复用经过校验的候选和回执，补齐配置后重试原标签。源码修复或动态包回退使用新候选版本及更高 revision；Play 已收到构建且回执无法恢复时，先核对轨道，再用更高构建号出新候选。

Linux 使用 `0.1.0-rc.9`、revision 和构建号 `1010` 补发，沿用上表的 Linux 验收项。RC8 的 Linux 构建生成了 DEB、AppImage 和签名，归档步骤进入 AppImage 中间目录后遇到符号链接而失败。补发只收集完成的安装包和签名，继续校验 AppImage 更新签名。
