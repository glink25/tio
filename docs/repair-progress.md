## 明确的能力边界

1. 文件分片限制物理文件体积，不是惰性文档编辑。当前编辑会话仍加载完整工作空间投影，数据库 UI 仍在内存中查询；分页宿主接口已建立，真正的远程查询 UI、全文索引及设备内存上限需要独立产品设计。没有把合成测试当成真实设备性能结论。
2. Local Folder 没有可靠内容指纹，仍需每轮读取对象 head。没有用 mtime 伪装强版本，也不承诺最小四方法文件接口具备 CAS/多文件事务。
3. chunks 暂不自动 GC，以免删除并发读者依赖的数据；未成功发布的分片会占用空间。已删除对象也不自动物理清理。
4. GitHub/WebDAV 具体鉴权、仓库选择和真实服务联调属于新连接产品能力，本次完成的是它们可直接复用的文件存储层。数据库后端无需依赖该层。
5. 当前文件实现是浏览器本地 API；停止同步等待已发出的 I/O。没有添加不能取消底层调用的虚假取消机制。未来网络 provider 应在其请求实现中提供真正的取消/超时，并明确结果未知时的重试语义。
6. 公开 npm SDK 发布、真实手机 IME/内存、原生目录权限、生产 GitHub/WebDAV 限流均不在自动测试覆盖内；这不是旧数据兼容或运行时兜底。
