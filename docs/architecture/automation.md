# 数据库自动化

规则是 `type: automation`、`schemaVersion: 1` 的独立业务对象，具备系统时间、删除标记和统一访问策略。空间设置提供规则管理，编辑器不运行调度器。规则通过命令、仓库、空间同步和 JSON 备份保存；未知字段继续保留，不读取历史格式。

## 规则与事件

`AutomationRule` 包含 `name/enabled/trigger/condition?/actions`。每个动作具有稳定 ID 和目标数据库 ID。字段和记录引用使用稳定 ID，不能跨空间。

- 页面：`page.created/page.deleted`，可选择整个空间、根页面或指定父页面的直属页面。仅显式删除对象产生事件；删除父页面隐藏的后代不合成事件。数据库不是普通页面。
- 记录：`record.created/record.properties/record.body/record.deleted/record.entersCondition`。属性可监听所有可编辑字段或指定字段。进入条件只处理更新时不满足到满足的变化，新建匹配用新增触发器。
- 条件支持 `all/any`，复用数据库筛选器的比较、空值和文本语义。页面条件可用 `id/title/body`。首版条件使用可编辑字段，不把公式、汇总、系统时间重算当作独立事件。
- 新增、修改或软删除记录可选择触发记录、指定 ID/前序动作 ID 数组或条件匹配。批量目标先收集全部 ID，再逐条写入。
- 属性值为 `{kind:'literal',value}` 或 `{kind:'reference',path}`。路径支持 `trigger/before/after` 的 `id/title/body/properties.<fieldId>`，`event.id/time` 和 `steps.<actionId>.ids`。不可用变量报 `variable`，不默认为空值。
- 正文为 `{mode:'append'|'replace',template}`，通过 `{{trigger.id}}` 等路径插值，每行生成普通文本段落。变量不重新解析，不执行 HTML 或脚本；追加保留原有不透明块。

例：页面创建后向“页面索引”数据库写入页面 ID；页面删除后使用 `before.id` 查找索引记录并软删除。页面创建可能发生在用户填写标题之前；新增事件只反映当时确认提交，不暗中等待用户填完标题。

## 提交边界与执行

`WorkspaceRuntime.subscribeCommits` 只通知本运行时确认提交的修改，包含提交 ID、时间、实际提交前后对象及结构化 `MutationSource`。CAS 重放沿用命令时间，恢复丢失回执只发一次事件；普通广播仅刷新投影，不作为第二个触发源。导入、同步、初次读取、规则启用和无变化提交不触发。撤销/重做的真实变化继续触发；恢复删除对象不视作新增。

`AutomationRunner` 从仓库的 `queryObjects` 分页读取规则和目标记录，通过 `runtime.ensure` 加载依赖，不读取 UI 挂载状态，也不要求完整内容缓存。文件 provider 的扫描成本由提供方承担。运行时保留的导航元数据不是命令基线。

自动化调用 `automationWrite`，复用 checked 命令、访问校验、时间维护和统一提交队列，不写用户撤销历史。提交前检查待处理命令和临时草稿，冲突即停止，不能覆盖未确认输入。临时草稿当前没有稳定字段范围，因此存在草稿时保守阻止自动化写入。AI 可通过 `checked(..., {source:{kind:'ai'}})` 标记主动编辑。

每条规则顺序执行，失败后停止后续动作，已提交结果不回滚。每条写入具有稳定动作标识，提交重试沿用同一提交 ID。链路传递根事件、父运行和规则路径，同一路径不能重复执行同一规则。默认上限为 8 层、100 次规则执行、1000 条记录写入；provider 可以收紧。客户端仅保存当前会话最近 100 次运行，错误判断使用结构化错误码。

客户端任务没有跨会话队列。会话关闭时丢弃尚未提交的任务；已开始的底层提交可能完成，已提交数据继续适用原仓库的恢复保障，不在重开后重放自动化事件。

## Provider 接入

`AutomationProvider` 提供 `capabilities/getRuns/subscribeRuns/dispose`。能力包括支持的触发器与动作、`session/server` 执行位置、事件来源、按需依赖读取、中断策略、历史策略和上限。没有能力接口就不启动执行器，不根据连接名称推测能力。

当前设备、文件夹、GitHub 的 `ConnectionBinding.automation` 创建共享会话执行器，宿主在空间打开后接入，随运行时关闭释放。绑定优先采用 `repository.automation`，因此服务端 provider 不会同时启动浏览器执行器。文件和 GitHub 的外部修改、后台同步不补发本会话主动编辑事件。

服务端 provider 在自身权威提交边界形成 `CommittedMutation`，自行选择事件窗口、执行身份和调度。共享 `AutomationRunner(..., {observe:false, capabilities})` 的 `accept` 可用于内存参考验证；生产服务端也可以实现自己的执行器。浏览器端不承担服务器任务存活。

`serveHost` 自动暴露 `tio.automation` v1 扩展：`{operation:'state'}` 返回能力与运行历史，`extensionChanged` 推送更新。`BridgeRepository.connect` 校验载荷后提供同一接口。来自桥接提交的来源由 `serveHost` 的可信 `trustedSource` 参数指定，默认 `editor`，忽略客户端伪造的自动化链路；AI、导入等可信入口应使用对应宿主身份。服务器事件必须由权威入口采集，不能直接把任意客户端请求当作触发上下文。

当前没有真实服务端实现。内存参考测试与 Chromium 测试不代表原生文件权限、真实 GitHub 端点或服务端部署已通过验证。

## 自动化中心与流程草稿

设置中的入口打开独立自动化中心，暂时收起设置，关闭后回到原位置。管理列表提供名称搜索、启停筛选、最近结果与删除；创建/编辑和运行日志为弹窗内独立视图。桌面流程采用左右两栏，移动端依次显示触发条件和操作。

未选触发器或动作的配置只存在于宿主 `FlowDraft`，不保存不完整业务对象。新建时不预选触发器、数据表和动作。“仅保存”保存完整的停用规则，“保存并启用”保存完整的启用规则；离开有修改的流程时可以继续编辑、放弃或保存后离开。提交失败保留输入，已提交命令的恢复仍经过原运行时，不创建自动化配置保存队列。

表单内字段输入直接更新草稿，统一在底部保存。共享 `FieldInput.commitMode: 'form'` 用于此场景，缺省仍为编辑器原有的显式确认模式。变量选择按步骤、变更前后和类型组织；未发生的前置状态、未来步骤、不同数据表的记录输出不提供。删除或移动步骤、删除字段造成的引用失效必须修正后才能保存，稳定引用不会按显示编号重写。正文变量使用可删除的标记展示，持久化仍是既有模板路径。

自动化中心仅展示 provider 实际保留的运行历史，客户端明确说明仅当前会话。独立弹窗不管理执行器生命周期，关闭弹窗不会停止空间会话中的自动化。

### 页面索引的动态提及

页面创建/删除事件提供“触发页面”变量。`trigger.mention` 返回 `{workspaceId, kind:'page', id}`，用于单条提及和提及相等条件；`trigger.mentions` 返回包含该引用的数组，用于多条提及字段。`before/after` 支持相同路径，但变量选择器只提供该事件确实存在的前后状态。记录事件不提供页面提及变量，不把普通字符串 ID 隐式转换为提及。

例如维护 post 页面下的 PageMap：第一条规则监听 post 的直属页面创建，在 PageMap 新增记录，把 post 提及字段赋为“第 1 步 · 触发对象 · 触发页面”；第二条规则监听同范围的页面删除，删除 PageMap 中 post 字段等于“第 1 步 · 触发对象 · 触发页面”的记录。变量按目标字段的单条/多条模式提供正确形状；相等筛选始终使用单条引用。删除时从事件的删除前快照构造引用，按完整身份比较，不依赖已删除页面的标题或实时可访问性。
