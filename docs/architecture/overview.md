# 整体架构

## 职责

连接负责授权与空间发现；当前一次使用一个连接，一个连接可有多个空间，一个逻辑空间只绑定一个同步端点。宿主管理连接、目录、导航、偏好、访问策略、仓库和后台调度；编辑器管理富文本、数据库交互与临时选择状态。

`EditorSession` 是 Web 组合与独立嵌入共享的编辑接口。数据流为：编辑意图 → `WorkspaceRuntime` 乐观队列 → `WorkspaceRepository` 提交 → 带版本与来源的变更事件 → 编辑投影。无界面命令也经过仓库；组件不自行读写 IndexedDB，也不维护独立保存队列。

设备仓库以 IndexedDB 为权威；文件夹直接发布文件，仅在浏览器保留恢复日志；GitHub 使用可离线编辑的完整文本副本，附件按需读取。缓存、原子性和离线能力由提供方声明，详见[提供方读取](provider-access.md)。

## 编辑与提交

运行时保留确认基线、乐观命令、紧凑回执和撤销记录。输入立即读取乐观投影；外部变更与提交回执串行处理，重放尚未确认的命令，避免输入回退。提交按稳定对象/字段 ID 操作；命令重放不重新生成时间戳或重复触发平台副作用。

提交校验身份、格式和访问权限。原子提供方使用空间版本 CAS；文件夹采用协作写入串行化与可恢复发布，不承诺多文件事务。提交只返回受影响条目。超时通过原提交 ID 查询结果；确认后压缩回执，用客户端序列水位防止重复执行。

关闭会话先刷新，失败保留待处理命令；切换空间不能丢失本地输入。远端失败不阻止已完成本地刷新的切换。仓库与同步调度独立于编辑器生命周期。

## 副本同步

`SyncCore` 处理内容发现、三方合并、发布与 ACK；`HostSyncRunner` 处理定时、可见性、锁、重试及完成通知。仓库事件驱动同步，包括其他窗口和无界面修改；同步写入标注来源，避免回声循环。

连续修改重置 1 秒尾随计时，轮询不抢跑；手动同步可立即执行。上传期间的新编辑继续保持脏状态。附件先于引用内容发布。授权拒绝保留本地草稿，恢复必须针对原身份与原端点，不能把草稿重绑定到其他账号。

直接文件夹仓库不运行副本同步链路。文件层负责稳定路径、编码和分片，不负责业务合并；GitHub 提供可选的快照和批量发布能力。

## 平台与边界

宿主拥有主题、语言和门户上下文；编辑器只接收 `Presentation`。共享 CSS 值不代表共享可变状态。构建通过 CSS 转换器限定编辑器样式，并检查产物边界。

纯领域、工作空间和同步包不依赖 React、浏览器存储或具体端点；依赖边界由 `scripts/check-boundaries.mjs` 检查。提供方和适配器归宿主，不能反向进入编辑器。

业务数据不含句柄、凭据、Blob URL 或 UI 实例。当前不读取或迁移历史格式；未知内容保留与历史兼容是不同要求。详见[数据契约](../protocols/data-format.md)、[编辑器接入](../../packages/web-editor/docs/integration.md)和[文件存储](../../packages/file-storage/docs/storage.md)。
