# 提供方读取与恢复

`WorkspaceRepository` 提供异步 `readObjects`、`queryNavigation`、`queryMentions`、`queryRecords`、`search`、`scan` 和 `readMetadata`，桥接提供相同能力。导航与提及元数据不包含正文，不能作为编辑命令的基线。缺失、拒绝访问和传输失败分别表达；加载状态支持重试。

先读取导航与当前正文，数据库嵌入独立请求结构、视图和记录页。当前正文固定保留，待提交命令阻止淘汰；干净且未固定的正文按 256 对象工作集目标淘汰。附件访问时读取。正文读取不推进变更游标；命令加载依赖后重放，不能覆盖现有乐观投影。

记录查询先过滤排序再分页，表格每页 100 条；分页是实时结果而非冻结快照。扫描提供方可能遍历全部文件。搜索可由提供方远程执行；浏览器实现把权限过滤后的批次发送到 Worker，逐步显示结果，不填充正文缓存。导出显式遍历完整空间，版本变化时最多重试三次，不能把局部投影当作备份。

## 能力声明

`storageCapabilities` 声明 `persistence: atomic | recoverable`、`offline` 和 `prefetch: none | all`。调用方按声明判断，不能通过连接名称猜测。

- 设备：IndexedDB 原子提交，不自动预取全部正文。
- 文件夹：直接文件读取与可恢复发布，不保留完整副本，不自动预取全部正文。
- GitHub：本地副本原子保存，支持离线，预取全部文本；初次同步不完整时拒绝搜索/导出。附件字节按需缓存。

## 文件夹恢复

发布前先持久化恢复日志，内容包括受影响对象、哈希、版本、回执身份和暂存附件；不含完整空间副本。附件先写，对象替换前重读校验。所有请求写入和完成回执结束才算保存成功，成功后丢弃待处理正文。

重试要求文件仍等于记录的原值或目标值；其他外部值触发冲突并保留日志。已知文件缺失不能推断为删除；删除使用显式标记。此机制不能保证多文件原子可见或外部写入 CAS。

失去目录权限后不能从正文缓存重新打开文件夹空间；保留目录入口，已打开编辑器在检测到权限丢失后只读。后台不得弹授权框，用户点击时直接发起权限请求。日志与待处理命令在恢复原端点授权后重试。

## 提及

`queryNavigation` 支持按 `text` 过滤；`queryMentions({text, after, limit})` 独立查询可见页面、数据库和记录，按标题过滤后以稳定 ID 分页，返回 `{items: [{reference, title, description?}], next?}`，记录摘要附带所属数据库名称。GitHub 协作者由宿主连接提供，并通过共享 `MentionService` 合并，来源失败独立表达，不影响内容候选。`readMetadata(ids)` 返回版本化条目以及独立的 missing/denied ID，不返回正文和记录属性；记录摘要的 `title` 由数据库标题字段派生，不持久化为另一份记录标题。

宿主提及服务合并读取，对后台通知采用 1 秒防抖、5 秒最长等待；初次解析、显式重试与已知权限变更立即处理。旧标题在刷新期间保留，已知拒绝则立即隐藏。失效目标不删除已存引用。扫描提供方不承诺与空间大小无关的读取成本。

## 自动化能力

自动化通过独立 `AutomationProvider` 接口声明触发器、动作、执行位置、来源、依赖读取、中断、历史和预算，不从存储名称或 `storageCapabilities` 推测。当前客户端提供方按需读取规则和目标数据库，会话关闭后不补跑。接入与桥接见[自动化](automation.md#provider-接入)。
