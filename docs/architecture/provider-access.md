# 提供方读取与恢复

`WorkspaceRepository` 提供异步 `readObjects`、`readProjection`、`queryNavigation`、`queryMentions`、`queryRecords`、`search`、`scan` 和 `readMetadata`，桥接提供相同能力。导航与提及元数据不包含正文，不能作为编辑命令的基线。缺失、拒绝访问和传输失败分别表达；加载状态支持重试。

先读取导航与当前正文，数据库嵌入独立请求结构、视图和记录页。当前正文固定保留，待提交命令阻止淘汰；干净且未固定的正文按 256 对象工作集目标淘汰。附件访问时读取。正文读取不推进变更游标；命令加载依赖后重放，不能覆盖现有乐观投影。

记录查询返回独立的 `QueryPage`，条目以 `projection` 表示身份、版本、时间和属性，不包含正文及未知 envelope 扩展。投影进入独立查询缓存，不能标记正文已加载或作为命令基线。编辑列表记录时先读取完整对象，保留正文、未知字段与不透明内容；关联展示只递归加载属性投影。记录查询先过滤排序再分页，表格每页 100 条；无筛选排序时按稳定 ID 范围取页，有筛选排序时只读取目标数据库及依赖属性，由 Worker 执行计算。分页是实时结果而非冻结快照，依赖版本不一致时重试。导航、提及和记录查询共用 provider 的派生索引，不调用全空间正文快照。搜索可由提供方远程执行；浏览器实现把权限过滤后的批次发送到 Worker，逐步显示结果，不填充正文缓存；同版本各批次复用导航上下文。导出显式遍历完整空间，版本变化时最多重试三次，不能把局部投影当作备份。

## 能力声明

`storageCapabilities` 声明 `persistence: atomic | recoverable`、`offline` 和 `prefetch: none | all`。调用方按声明判断，不能通过连接名称猜测。

- 设备：IndexedDB 原子提交，同时维护查询投影，不自动预取全部正文。
- 文件夹：文件权威、直接文件读取与可恢复发布；浏览器只保存可重建投影、对象哈希和恢复状态，不保留完整正文副本。首次无索引时后台分批构建，当前已指定文档可先读取编辑；后续打开复用索引。`queryIndexState` 与 `subscribeQueryIndex` 表达 building/ready/error，与全文同步的 contentReady 分开。索引未完整时记录查询返回 pending，不把局部结果当完整数据库。
- GitHub：本地副本原子保存，支持离线，预取全部文本；初次同步不完整时拒绝搜索/导出。附件字节按需缓存。

GitHub 仓库发现逐仓库校验工作空间对象，格式错误或缺失的内容不进入发现结果，也不抢占新空间的端点绑定；已有绑定与本地草稿保留。授权、限流和网络失败仍按连接错误处理。文件解码使用结构化 `StorageError`，不会把传输失败归类为格式错误。

宿主通过 `ConnectionBinding.isContentReady(workspaceId)` 查询首次内容就绪状态；未声明时沿用空间打开完成语义。GitHub 复用持久化的完整同步标记，对象完整接收后即通过仓库事件逐步显示导航和正文，不等待全文下载。父级未到达的子节点暂时隐藏，不改写层级或提前修复树；已指定目标保持等待，不提前判定丢失。首次全文下载完成后先刷新当前运行时导航，再发布完整就绪状态。初始无可用页面时显示骨架屏，只有确认就绪且没有页面时显示空页面插画；后续后台同步不重置该标记。

副本初始化由通用宿主同步调度管理，独立于工作空间 `manualSync` 策略。同步绑定提供 `initialization.isComplete/complete`，完成状态由提供方持久化；宿主在空间锁内重读状态，统一恢复未完成的初始化。本地新建空间直接完成初始化，不启动远端拉取。初始化以远端快照为基线，原子接收对象、基线和恢复信息，本地未发布修改保持脏状态；用户主动同步可在初始化后继续执行双向同步。仓库 `contentReady` 和运行时同名状态表示全文就绪，单个对象是否可用仍按对象加载状态判断。初始化期间数据库记录/结构查询以 `HostError(pending)` 表达，搜索、导出、全空间扫描和自动化执行等待完成，避免把部分数据当作完整结果。

## 文件夹恢复

文件夹的外部文件修改仅通过显式 `refreshExternal()` 接收；宿主手动刷新先 flush，再核对当前空间文件。周期轮询只检查授权及 Tio 自身的持久化变更水位，不遍历目录。Tio 内部提交原子更新派生索引与变更水位，并通过广播通知其他窗口；广播遗漏可从水位恢复。目录发现只枚举直属空间目录和空间对象，不遍历空间正文及附件。

恢复元数据、投影、待完成发布和回执按键存储，单条提交及回执查询只读取受影响对象和 schema 依赖。`readChanges(since, ids)` 只为所需正文返回完整对象，其他导航变更返回元数据；未指定 ids 时保留显式完整增量读取。发布前先持久化恢复日志，内容包括受影响对象、哈希、版本、回执身份和暂存附件；不含完整空间副本。附件先写，对象替换前重读校验。所有请求写入和完成回执结束才算保存成功，成功后丢弃待处理正文。

重试要求文件仍等于记录的原值或目标值；其他外部值触发冲突并保留日志。已知文件缺失不能推断为删除；删除使用显式标记。此机制不能保证多文件原子可见或外部写入 CAS。

索引构建分代采集派生状态，发布时合并构建期间已确认的 Tio 修改；失败保留旧索引并报错，不覆盖输入。当前授权仍在索引读取前检查，文件写入前重验原内容，不把索引或弱 mtime 当作外部 CAS。

失去目录权限后不能从正文缓存重新打开文件夹空间；保留目录入口，已打开编辑器在检测到权限丢失后只读。后台不得弹授权框，用户点击时直接发起权限请求。日志与待处理命令在恢复原端点授权后重试。

## 提及

`queryNavigation` 支持按 `text` 过滤；`queryMentions({text, after, limit})` 独立查询可见页面、数据库和记录，按标题过滤后以稳定 ID 分页，返回 `{items: [{reference, title, description?}], next?}`，记录摘要附带所属数据库名称。GitHub 协作者由宿主连接提供，并通过共享 `MentionService` 合并，来源失败独立表达，不影响内容候选。`readMetadata(ids)` 返回版本化条目以及独立的 missing/denied ID，不返回正文和记录属性；记录摘要的 `title` 由数据库标题字段派生，不持久化为另一份记录标题。

宿主提及服务合并读取，对后台通知采用 1 秒防抖、5 秒最长等待；初次解析、显式重试与已知权限变更立即处理。旧标题在刷新期间保留，已知拒绝则立即隐藏。失效目标不删除已存引用。扫描提供方不承诺与空间大小无关的读取成本。

## 自动化能力

自动化通过独立 `AutomationProvider` 接口声明触发器、动作、执行位置、来源、依赖读取、中断、历史和预算，不从存储名称或 `storageCapabilities` 推测。当前客户端提供方按需读取规则和目标数据库，会话关闭后不补跑。接入与桥接见[自动化](automation.md#provider-接入)。

## 工作空间管理

工作空间删除与分享属于连接生命周期，不属于编辑命令或底层文件 I/O 契约。核心 `WorkspaceAction` 是无框架依赖的行为描述；宿主 `ConnectionBinding.workspaceActions(workspaceId)` 按空间返回可选的 `delete`、`share` 能力。未声明的操作不显示。行为包含由连接集成本地化的标题、说明、确认文案，以及 `direct` 异步执行函数或 `external` 网页地址；宿主统一呈现确认弹窗。

设备直接删除对应实例的对象、附件、暂存、回执和恢复数据。文件夹适配器仅递归删除 `workspaces/<workspaceId>/`，校验 ID 并清理对应恢复日志，不删除连接根目录。两者均不提供分享。GitHub 适配器提供仓库设置和协作者管理网页地址：操作影响整个仓库，权限由 GitHub 管理。跳转不会触发 API 删除、邀请、本地清理或成功判断，404 也不能证明已删除。

宿主在删除前记录持久化生命周期状态，通过空间级 Web Lock 让删除与仓库调用互斥，阻止新写入；正常仓库调用持共享锁，可保持并发；广播通知其他窗口停止旧会话。运行时丢弃排队输入并等待已开始工作结束，停止恢复与后台任务后执行 provider 删除。生命周期状态保留在空间数据命名空间之外，旧会话不能通过提交或保存目录项重新创建空间。删除失败保留目录项与状态，允许重试，不恢复后台写入。成功后清理目录项和个人偏好；删除当前空间返回原连接的空间列表。该状态仅用于防止删除竞争，不是内容格式兼容或迁移机制。

## 引用查询与图谱

`WorkspaceRepository.relations?: RelationsProvider` 是独立的可选读取能力：

- `queryReferences({id, direction: 'in' | 'out', after?, limit})` 返回关联文档分组。
- `queryReferenceOccurrences({sourceId, targetId, after?, limit})` 返回摘要及来源/目标 ContentTarget。
- `queryGraph({after?, limit})` 分页返回全空间节点和有向边，包含无关联的可见文档。
- `subscribe(listener)` 通知 `content`、`ready`、`access` 失效。提供方必须在访问策略变化时发出 access；消费者立即清空旧数据，不保留权限撤销前的标题和摘要。

结果包含版本、`building | partial | ready`、`complete`、items、可选 next/total。complete 表示索引完整，next 表示仍有下一页，两者独立；total 只在完整结果中提供。游标绑定查询及版本，失效使用 conflict，不混合不同版本的结果。不存在能力用 unsupported 表达，不能用空图代替。

权限过滤由 provider 完成，覆盖节点、边、摘要及计数；当前正文已有但不可用的出向目标仅返回空标题及 unavailable 状态。关系结果不是权限凭据，打开目标仍走正常读取检查。

当前提供方从查询投影及持久化的正文引用摘要按需异步建立引用索引。首次读取完整派生集；后续只读取 changedIds 对应投影，复用来源 revision 对应的提取结果。数据库字段定义变化重算记录提及字段，不重新读取正文；权限变化清空派生结果后重新过滤。不进入编辑器正文缓存，也不作为保存确认的前置条件。GitHub 首次文本同步未完成时返回 partial，完成后主动失效。远程提供方可自行实现异步索引并通知完成，无需浏览器下载全空间。

UI 在确认提交、撤销重做和同步接收后重新查询，以 provider 结果为准，不拼接乐观关系。首次加载及重算显示更新中，失败可重试；切换空间丢弃旧响应。

搜索结果使用 `SearchHit {id, target, title, path, excerpt}`，命中标题、块或记录字段都使用 ContentTarget，结果不返回正文对象。扫描搜索的分页仍按扫描批次推进，一个批次可以包含多个命中。

图谱分页先返回节点，再返回引用这些节点的边。前端按批次追加，保留已存在节点坐标；首次布局采用按需加载的 Cytoscape/fCoSE Worker，小图使用力导向优化，大图使用谱布局，避免布局计算阻塞编辑器主线程。视觉坐标只保留在当前图谱界面，不写入 provider；窗口尺寸变化重新适应画布。

数据库表格通过 `queryRecordWindow({databaseId,view?,text?,offset,limit,expectedVersion?})` 返回 `{version,offset,total,entries}`。total 只统计权限内、未删除且在当前查询中可见的记录，位置采用筛选排序后的绝对序号；同值以稳定 ID 排序。expectedVersion 不一致返回 conflict，不拼接跨版本区间。游标查询与区间查询复用投影查询语义；按提供方版本和访问策略版本缓存有限个有序 ID 集合，不保存正文副本。普通记录写入可增量更新 ID 顺序，其余依赖变更使缓存失效。

完整结果集滚动条不表示预读所有记录。Glide 使用总行数和可视区域回调，桌面表格与移动端虚拟列表共用每批 100 行、最多 10 批的视口缓存；区间释放同时释放运行时的窗口投影。未加载行不可编辑或参与批量操作，选择按实际记录 ID 保存。文件夹首次建立投影索引和复杂筛选的全候选计算仍独立于视口懒加载。
