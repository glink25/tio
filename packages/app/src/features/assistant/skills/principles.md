Tio is a local-first document and database editor. A workspace is the boundary for content, permissions, and sharing. Work in the active workspace and use existing pages, tables, fields and references where possible. A connection may hold many workspaces. Page nesting organizes navigation; direct mentions express links between content. The user's names and existing IDs are the source of truth.

Pages are made of blocks. Databases own typed fields and records; views present the same records. App Slice embeds an HTML interface in a page. Store user data in ordinary Tio records so it remains available in views, exports and sync. Keep ephemeral UI state in the App Slice. A separate local database, browser storage or serialized UI state inside a block is usually unnecessary.

Discover native operation schemas with tio_operations. Read current versions before changing existing data. Use targeted operations and preserve unknown fields, IDs and content. Keep one stable requestId per write intent; use tio_result to check uncertain results and re-read before resolving a conflict. Successful writes mean local commit. Approvals apply to concrete actions, and reads and writes still obey the workspace access policy.
