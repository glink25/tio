# GitHub 存储

GitHub 账号作为连接，每个仓库对应一个空间。浏览器保留完整文本副本，私有附件按需下载。PAT 模式无需服务端，GitHub App 登录使用[鉴权 Worker](../../../apps/auth/docs/deployment.md)；文档流量直接访问 GitHub。

## 连接与发现

PAT 需目标仓库 Metadata 读与 Contents 写权限，创建仓库还需相应创建权限。候选仅包含可访问的 `tio-*` 与 `<owner>.github.io`，并检查 `workspaces/<id>/objects/<id>.json` 标记；无标记仓库忽略，多个标记或重复绑定报错，不任意选择端点。

App 枚举安装仓库，PAT 分页查询用户仓库。登录和恢复连接后自动发现。新空间创建用户账号下的私有 `tio-<workspaceId>`；失败立即报告，不保存待重试创建。尚不提供组织仓库创建、分支选择或仓库删除。

初次绑定实际默认分支，以后不因默认分支改变而自动换端点。数字仓库 ID 允许仓库改名，空间名与仓库名独立。副本命名空间含连接、仓库与分支；断开连接删除凭据并停止调度，保留可恢复内容。

## 发布与同步

`GitHubProvider` 提供文件 I/O、不可变快照与批量发布；`GitHubAdapter` 负责身份和仓库生命周期，文件层负责业务编码。编辑器不依赖 GitHub。

每批读取固定 Git commit，Blob SHA 为强指纹。Web 宿主注入 `GitHubCache`，使用 IndexedDB 保存远端 head、tree、完整路径/SHA 映射和已读取的文件字节，按账号、数字仓库 ID、分支和空间隔离，与本地编辑副本及 ACK 分开；内存缓存只作为有界加速。文本和分片不受内存缓存条数或大小限制，附件仍按需读取。

每轮重新请求 ref，head 未变时复用完整结构，变化时读取对应 tree；递归树截断后显式遍历子树，完整后才保存结构。文件读取根据 API 返回的 SHA 查找本地字节，仅新增、变化或缓存缺失时下载。分片按自己的 SHA 读取并校验内容，不能仅根据对象清单跳过子文件检查；下载失败不记录成功缓存，也不视为远端删除。

发布前计算 Git Blob SHA（SHA-1，含 `blob <字节数>\0` 头），过滤相同内容和不存在文件的删除，不与分片路径的 SHA-256 混用。只为变化文件创建 blob，在原 base tree 上一次创建 tree/commit，以原 head 为父提交，用非强制 ref 更新发布；无有效变化时不产生提交。竞争时重新读取并合并，最多三次立即尝试；不能把旧合并结果直接挂到未见过的新 head。ref 响应丢失后核对 commit/history。确认发布后，使用 API 返回的 SHA 保存已上传字节和新结构，下一轮无需重新下载自己发布的文件。

发布成功后才 ACK，上传期间的新修改仍脏。普通 write 必须持久完成，缓冲只限显式批量接口。保留删除标记，不清理无关文件或分片。

本地副本声明 atomic/offline/prefetch-all，初始文本未完整同步时拒绝搜索/导出。已有文本可离线编辑，远端附件元数据可先于字节到达；新本地附件仍需暂存字节，单文件限 20 MiB。

使用共享 1 秒尾随防抖，可见时每 60 秒轮询，并在网络/可见性恢复时唤醒；限流期限推迟重试。仓库/分支访问失败不是远端删除，重新授权必须匹配原数字用户 ID。

自动测试验证跨实例持久缓存、增量下载与分片完整性、文件级去重、批量发布、竞争恢复及上传期间的编辑保留；不代表真实 App 安装、Worker 部署或生产限流联调通过。
